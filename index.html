Project Overview

KlashOut is a music competition and social platform combining real-time gaming, streaming, and a digital economy. Users compete in head-to-head "Klashes" where audience votes determine winners.

Phase 1 Scope: Requirements engineering and system design specification. This phase produces technical documentation to enable unambiguous Phase 2 implementation.

Architecture Summary

Design Approach

API-First, Client-Agnostic Backend — Mandated by web-first sequencing. All business logic resides server-side; web and future mobile clients are thin presentation layers consuming the same API.

Technology Stack (Cost-Optimized)

Layer Technology Rationale
Backend API Node.js + Express.js JavaScript full-stack, WebSocket support
Database DigitalOcean Managed PostgreSQL ACID-compliant, 48% cheaper than AWS RDS
Real-Time Socket.io Room-based pub/sub for Klash events
Cache Upstash Redis (serverless) Pay-per-command, free tier covers early stage
File Storage + CDN Cloudflare R2 Zero egress fees, 97% cheaper than S3 at scale
Frontend (Web) React + TypeScript React Native code sharing for mobile
Frontend (Mobile) React Native iOS + Android from single codebase
Payment Stripe → Helcim (at £50K+/mo) FCA-licensed, lower fees at scale
Hosting DigitalOcean Droplets/App Platform 40% cheaper than AWS EC2, predictable pricing

Estimated savings: 60-80% vs AWS-heavy stack. See Cost Optimization for full analysis.

Key Design Decisions

  • Double-Entry Ledger — Wallet implemented as internal ledger with ACID transactions, not blockchain
  • Modular Monolith — Clear service boundaries (User, Klash, Wallet, Music, Social) enable future microservices migration
  • Horizontal Scaling — Stateless API servers, Redis pub/sub for multi-server WebSockets
  • Partnered FCA Compliance — Stripe/Mangopay handles e-money licensing vs KO applying for own license

Data Model Overview

Core Entities

The data model splits into two subdomains:

Social / Gaming Core

  • User — Authentication, profiles, tier (Klasher/Independent/Super)
  • Genre — Controlled vocabulary for Klash spaces
  • Track — Music files (user-uploaded or licensed catalogue)
  • Playlist — User-curated track collections
  • Klash — Game instances with state machine
  • KlashParticipation — Associative entity (User ↔ Klash with role, track, outcome)
  • Vote — Audience votes during klash
  • Tournament — Organized competitions (Round Robin, Swiss, Elimination)

Economy

  • Wallet — Polymorphic (belongs to User OR Klash for pot escrow)
  • Transaction — Double-entry ledger (from_wallet_id → to_wallet_id, all types unified)

Key Modelling Decisions

  • Tier as attribute — Not an entity (3 fixed values: Klasher, Independent, Super)
  • Genre as entity — Referenced by both Track and Klash
  • Transaction types unified — Single table with discriminator (top-up, gift, purchase, winnings, cash-out)
  • Balance stored-but-derived — Wallet.balance updated atomically, recomputed daily for audit
